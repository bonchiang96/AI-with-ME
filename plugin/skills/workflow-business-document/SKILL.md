# Business Document Development Workflow

1. Apply the complete [Business Document Development Workflow](references/workflow.md).
2. Let the user select this Workflow for the Task.
3. Use the selected Identity's shared Role Lifecycle and normal approvals.
4. Let the Meeting Agent agree the brief, gather sources and confirm structure with the user.
5. Let the shared Execution Agent write a full draft with complete QA.
6. Give the user a separate review in a Meeting.
7. Apply the [revision ownership rule](../system-entry/references/identities-and-commands.md#2-agent-responsibilities-and-commands).
8. Produce numbered revisions from the previous draft, relevant Closed Minutes and appropriate Knowledge Bases.
9. Record a user-approved Stable version in the Minutes and use it as the later baseline.
10. Keep Workflow progress in the current step owner's Identity Context.
    Transfer ownership only through normal handoff.

Select subject knowledge through [Knowledge Base](../knowledge-base/SKILL.md).
Use [Quality criteria](../workflow-qa/references/quality.md) and the correct packaged [Writing Mode](../../rules/global-writing-rules.md#2-writing-modes).
Sending a Stable document to an external reader still requires applicable authorization.
