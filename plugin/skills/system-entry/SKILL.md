# System Entry

## 1. Establish the starting context

1. Read the packaged [Global Writing Rules](../../rules/global-writing-rules.md) and [Global Communication Rules](../../rules/global-communication-rules.md).
2. Reuse static instructions already effective in this Conversation unless their applicability changes.
3. Check the available Google Drive and Google Docs capabilities and their permissions.
   Check actual access for the requested action. A connected tool name alone does not prove access.
4. Explain any missing connector, permission or capability and its practical limitation.
   Discuss the next authorized step. Perform or guide permitted setup within available capabilities.
   Missing Google access limits governed runtime actions. It does not prevent Plugin installation.
5. Locate the central Google Drive folder named **AI with me** and open its System Context.
6. Read applicable System Rules once at Conversation start. Apply any user communication overrides there.
7. Let the user select a registered Identity. Resolve its exact Agent Key, Role, Responsibility, Scope and identity folder.
8. Open that folder's authoritative **00 Identity Context** and **01 Index**.
9. Load the shared [Meeting Agent](../meeting-agent/SKILL.md) or [Execution Agent](../execution-agent/SKILL.md) Lifecycle for the selected Role.
10. Continue through that Lifecycle using current context, source references and progress checkpoints.

## 2. Resolve the governing resources

1. Apply [Operating Principles](references/principles.md) to source authority, autonomy, Scope and interpretation.
2. Use [Foundation](references/foundation.md) for governance resources, identity folders, indexes, Knowledge Bases and templates.
3. Use [Identities and Commands](references/identities-and-commands.md) for registration, role boundaries and dynamic Command resolution.
4. Use [Environments](references/environments.md) for local work, result return and deferred design boundaries.
5. Read relevant dynamic Google information when current data is needed.
   Installed instructions support normal operation without routine GitHub reads.
6. Discover applicable Commands through Identity Context operating references.
   Use the packaged [Command definitions](references/commands.md) where applicable.
   Resolve current destinations and customization before an action.

## 3. Establish a missing System or Identity

1. Confirm that the central Root is absent before Bootstrap. Inaccessibility alone does not establish absence.
2. Use the provisional Meeting Agent and normal Meeting Lifecycle in [Bootstrap and Identity setup](references/identities-and-commands.md#1-identity-selection-and-governed-setup).
3. Obtain user approval for the arrangement and creation actions in that Meeting.
4. After CLOSE MEETING, let the same Meeting Agent perform the approved setup and save the first records.
5. Establish **general-meeting** and **general-execution** as the minimum Identities.
6. Rejoin the normal entry path at Identity selection.
7. Define later scoped Identities through the General Meeting Agent's approved Meeting and Post-Meeting Actions.
8. For local Bootstrap, establish only missing Local System Rules and required working paths.

Use the [System Context template](../../templates/system-context.md) and [System Rules template](../../templates/system-rules.md).
Use the [Identity Context template](../../templates/identity-context.md) for approved Identity setup.
Keep detailed undecided arrangements visible rather than inventing governance.
