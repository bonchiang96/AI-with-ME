# Book Development Workflow

1. Apply the complete [Book Development Workflow](references/workflow.md).
2. Let the user select this Workflow for the Task.
3. Use the selected Identity's shared Role Lifecycle for every Meeting or Execution step.
4. Discover Book knowledge through [Knowledge Base](../knowledge-base/SKILL.md).
5. Keep progress in the current step owner's Identity Context. Transfer ownership through a normal handoff.
6. Preserve the user's core thinking and intended meaning. Contribute new ideas only when explicitly requested.
7. Use one full draft by default. A large Book may use the approved Chapter customization.
8. Apply the complete [review revision rule](../system-entry/references/identities-and-commands.md#2-agent-responsibilities-and-commands).
9. Verify each actual draft using [Quality criteria](../workflow-qa/references/quality.md).
10. Complete and publish the Base Edition before a separate additional-language redraft cycle.

The linked Workflow owns its detailed stage outcomes, Book Foundation, reader decisions, architecture and edit criteria.
Its scope does not authorize a new Meeting, Job or publication by itself.
