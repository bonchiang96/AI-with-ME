# Inbox

## 1. Resolve the message authority

1. Apply [Records, Messaging and Experiences](references/records-messaging-experience.md).
2. Resolve exact sender and recipient Identities from the central System Context registry.
3. Match Responsibility, work type, Scope and relevance. Hold ambiguous recipients pending.
4. Preserve each Identity's separate inbox and assignment.
5. Treat messages as advisory. Receiving a request does not grant execution approval.
6. Use the [Inbox template](../../templates/inbox.md) for the Google Docs native table.

## 2. Read and process

1. Read the inbox at the point selected by the active Role Lifecycle.
2. Open each message's referenced closed record and retain its Ref and From relationships.
3. Route every relevant outcome to its authoritative owner.
4. For Execution, retain valid pending Work Requests in Future Topics under the [Execution Lifecycle](../execution-agent/references/lifecycle.md).
5. For Meeting, retain unselected new matters only when the user chooses future consideration.
6. Register newly appearing Deliverable packages when processing their Completion Notices under [Foundation](../system-entry/references/foundation.md#5-identity-folder-index-and-inbox).
7. Preserve essential meaning and sources, then delete the processed inbox row.
8. Present suggested follow-up as a proposal within normal Scope and approval boundaries.

## 3. Send

1. Establish the message's authorized origin, recipient relevance and authoritative sources.
2. Use Work Request for bounded proposed work. Use Completion Notice for verified outcomes after the full assigned Protocol.
3. Add one row to the recipient's inbox: Sent, From, Type, Ref and Message.
4. Set Ref to the key in the sender's index for the closed originating record.
5. Apply packaged [Writing Rules](../../rules/global-writing-rules.md) Strict Mode to the final message.
6. Verify the exact saved row and routing Identity.
7. Report the actual send result. A saved row does not prove that the recipient read it.

For Experience search and capture, use [Knowledge Base](../knowledge-base/SKILL.md).
Messages and index rows reference authoritative resources rather than copying complete document bodies.
