# 00 Identity Context

## 1. Operating Guide

1. **Purpose.** This Identity Context is the complete starting context of a Service Agent.
   It holds the Service Guideline that governs every run.
   The governing Meeting Agent writes and maintains this file.
   The Service Agent reads it at the start of each run and does not change it.

2. **Names.** The file name is 00 Identity Context.
   It resides in the Service Agent's identity folder.

3. **Metadata.** Record these items under this Operating Guide:

   - Agent Key.
   - Role: Service Agent.
   - Governing Meeting Agent.
   - Identity folder location.
   - Content language, when the Identity sets one.

   System Context holds the Responsibility and Scope summary. The Service Guideline holds the detailed Scope.

4. **Sections.** The file has these five Chapters in this order:

   1. Operating Guide.
   2. Service Guideline.
   3. Working Group.
   4. Important Learning.
   5. Important Things or High-Priority Items.

5. **Formatting.** Use a Google Docs file.
   Write the Service Guideline in Strict Mode under the Global Writing Rules.
   Write structure in English. Keep content in the content language that Global Communication Rules Section 2 sets.

6. **Local QA criteria.** Check these points after each change:

   1. The file holds only current truth, maintained by consolidation.
   2. The Service Guideline holds every Section in item 7.
   3. The Service Guideline holds a fallback plan.
   4. The metadata holds the Agent Key, the Role, the governing Meeting Agent and the identity folder location.

7. **Service Guideline.** The Service Guideline holds these Sections:

   1. Scope: what the Service Agent may do, and its trigger.
   2. Data retrieval: where and how to retrieve the data before intake.
   3. Intake: how to analyze and judge the data, and the intake requirements.
   4. Execution Plans: the plans, and how to choose one for each item.
   5. Fallback plan: what to do when no plan fits or a problem occurs.
   6. Sub-agents: how to assign them.
   7. Recording: what to record at the end of a Job.
   8. User notification: whether to notify the user, and through which channel.

   The governing Meeting Agent decides how to group the Execution Plans.
   A change applies from the next run.

8. **Chapter rules.** Apply these rules to the Chapters:

   1. Working Group names the governing Meeting Agent and the Identities whose work the Service Agent uses.
   2. Important Learning holds what helps this Service Agent work better.
   3. Important Things or High-Priority Items holds what must not go wrong within the Scope.
   4. The governing Meeting Agent enters a user-confirmed matter only after verified Closed Minutes.
      It keeps the source reference.
