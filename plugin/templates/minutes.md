# 04 Minutes

## Tab 1. Operating Guide

1. **Purpose.** Final Minutes give a consolidated, independently readable account of one Meeting.
   Later Execution reads them for applicable instructions without the Meeting Record.
   Closed Final Minutes are immutable.

2. **Names.** The file name is 04 Minutes.
   It resides in a Meeting Agent's identity folder.
   Each Meeting has one Tab.
   Name each Tab with the tab name pattern in the Google System Rules.
   An example is 2026-10-27 — Plugin Branch Comparison — M-0257.

3. **Metadata.** Each Final Minutes identifies:

   - Meeting ID: an M key.
   - Identity.
   - Role.
   - Topic.
   - Focus.
   - Expected Outcome.
   - Status: Closed.
   - Opening Time.
   - Closing Time.
   - Meeting Record Locator.

4. **Sections.** Each new Final Minutes Tab starts with these five Chapter headings:

   1. Meeting Information & Agenda.
   2. Confirmed Findings & Decisions.
   3. Actions & Outcomes.
   4. Open Matters & Dispositions.
   5. Sources & Quality Verification.

   The Meeting Agent determines subject grouping, heading hierarchy, order and presentation inside each Chapter.
   Organize by related subject matter without requiring Agenda chronology.

5. **Formatting.** Use a Google Docs file.
   This Operating Guide is the first Tab.
   Each new Final Minutes is a new Tab.
   Use Strict Mode under the Global Writing Rules.

   Write structure in English. Keep content in the content language that Global Communication Rules Section 2 sets.
   Keep User's words with each material Decision the user expressed.
   Write each time in the Google System Rules date and time format.
   With an Agent workspace, the Final Minutes are drafted there and sync to Google at Meeting close.

6. **Local QA criteria.** Verify Content, Writing and Formatting separately.
   Record PASS or FAIL for each dimension in Chapter 5. Check these points:

   1. Every Metadata item is present.
   2. Each Finding keeps its observation, evidence, Scope and limitations.
   3. Each material Decision keeps its User's words under Global Communication Rules Section 2.8.
      It also keeps its supported Rationale, Design Intent, Assumptions, Conditions, Qualifications and trade-offs.
   4. The Handoff Plan is present.
   5. Each Deliverable has its agreed storage place.
   6. Each Deliverable this Meeting decided has its full Guideline content.
   7. Each Deliverable this Meeting decided has its executor and any Execution arrangement.
   8. Deliverable work in this Meeting has its agreed Plan, accepted Deliverables, review Decisions and Stable Decision.
   9. Material gaps are identified without speculation.
   10. The file holds only current truth.
