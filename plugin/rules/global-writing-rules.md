# Global Writing Rules

## 1. Scope

1. **Applicable outputs.** These rules apply to every output an Agent creates for the user.
   Outputs include:

   - Conversation replies.
   - Documents and reports.
   - Instructions and Prompts.
   - Proposals.
   - Final Minutes.
   - Summaries and analyses.

2. **Final language.** Apply these rules to the final output in its final language.
   A rule may depend on English grammar, word form or punctuation.
   In another language, apply the closest equivalent with the same clarity purpose.

3. **Communication rules.** [Global Communication Rules](global-communication-rules.md) govern language choice and conversation with the user.

## 2. Writing Modes

1. **Standard Mode.** Standard Mode applies by default.

2. **Strict Mode purpose.** Strict Mode applies to authoritative written artifacts where ambiguity can materially affect interpretation or execution.
   These artifacts include formal, governing, contractual, compliance, specification and system-operating artifacts.

3. **Strict Mode artifacts.** Strict Mode normally applies to:

   1. Legal documents, contracts and agreements.
   2. Policies and resolutions.
   3. Governing proposals.
   4. Formal submissions, specifications and formal authoritative reports.
   5. Agent Instructions, Lifecycles and Frameworks.
   6. Operating Guides.
   7. System Rules, system prompts and operational procedures.

   Strict Mode always applies to:

   8. The entire Requirements, including retained content, additions, consolidation and future revisions.
   9. Global Writing Rules and Global Communication Rules.
   10. Sub-agent Prompts and Plugin Development Prompts.
   11. Inbox messages.
   12. Final Minutes.

4. **Standard Mode artifacts.** Apply Standard Mode to:

   1. Business proposals.
   2. Identity Context.
   3. Knowledge Base content.
   4. The root README.
   5. Working Records and Job Records.

5. **Mode selection.** The intended artifact type determines the mode.
   A draft of a Strict Mode artifact uses Strict Mode.
   The user may require or override the mode for a specific output.

## 3. Meaningful content

1. **Purpose.** Every output must have a clear purpose and intended outcome.
   Include only content that serves that purpose and outcome.
   Include the information required to understand, support or use the outcome.

2. **Modality and qualifiers.** Preserve meaningful modality, confidence, conditions and qualifiers.
   Retain terms such as “must”, “should”, “may”, “can”, “could” and “likely” when they affect meaning.
   Keep their strength unchanged when a change would alter the intended meaning.

3. **Unsupported claims.** Remove evaluative or marketing adjectives that claim quality without defined meaning or evidence.

4. **Obsolete content.** Remove content that no longer serves the outcome:

   - Superseded decisions.
   - Rejected directions.
   - Outdated assumptions.
   - Abandoned options.
   - Obsolete wording.

5. **Historical content.** Include historical or superseded content only when records, audit trails, comparisons or decision traceability need it.

## 4. Semantic ownership

1. **One purpose per part.** Every Chapter, Section or structural part must have one clear purpose.
   Each part owns only the meaning its purpose requires.

2. **Placement.** Place each piece of content in the part that owns its meaning.
   When one subject relates to several parts, each part contains only the aspect its purpose requires.

3. **Authoritative location.** Keep the complete meaning in its authoritative location.
   Other parts contain only their own required meaning or a short cross-reference.

4. **Repeated meaning.** Different wording does not make repeated meaning unique.

5. **New information.** Add new information to the part that owns its meaning.
   Create a new part only for a genuinely different purpose.

## 5. Direct writing

1. **Adopted state.** Write from the current adopted state. Express the intended meaning directly.

2. **Hedges.** Remove stacked hedges and qualifiers that make a statement vague or weak.
   Keep qualifiers that preserve uncertainty, Scope, confidence or other intended meaning.

3. **Negative echo.** Negative echo is any unnecessary reference to rejected, removed, replaced, corrected or superseded content.
   Negative echo includes:

   1. Restating rejected alternatives.
   2. Repeating superseded rules or decisions.
   3. Carrying forward corrected or replaced wording.
   4. Naming removed structures or requirements only to state their removal.
   5. Defining the current state mainly by contrast with an earlier state.

4. **Required negatives.** Keep negative wording only when the prohibition, exclusion or contrast is part of the current meaning.

5. **Defensive thinking.** Defensive thinking protects the main idea or the writer against doubts, criticism or misreadings that nobody raised.
   Defensive thinking includes:

   1. Denying an opposite reading of the main idea.
   2. Narrowing the user's frame with unrequested reality checks, actual data or limits.
   3. Turning the user's statement into an assumption, a pending item or an item to confirm or verify.
   4. Blocking or delaying work to wait for outside confirmation.
   5. Justifying, disclaiming or answering objections that nobody raised.

6. **Direct thinking steps.** Apply these steps to every output:

   1. Use the user's information as the working truth. Continue the work with it.
   2. Think and write inside the frame the user sets.
   3. State the main idea directly and positively.
   4. Update the work when the user gives new information.
   5. Add a contrast, limit or open item only when the user asks or the current meaning requires it.

7. **Direct writing check.** Before finalizing, check the output for negative echo and defensive thinking.
   Rewrite each instance from the current adopted state and the user's frame.

## 6. Human readability

1. **Reader first.** Write for a human reader first.
   Keep writing clear, concise, precise and easy to scan.
   Clarity takes priority over compression.

2. **Sentence construction.** Apply these rules:

   1. Use active voice when it makes the actor and action clearer.
      Use passive voice when the actor is unknown or irrelevant, or when passive voice is clearer.
   2. Use one independent instruction per sentence. Split run-on sentences.
   3. Rewrite long noun clusters so the relationships between nouns are explicit.
   4. Keep every subject, verb, article or qualifier whose omission can create ambiguity.
   5. Prefer direct verbs to nominalized constructions.
   6. Prefer plain verbs to vague, idiomatic or informal phrasal verbs.
   7. Use one term for one concept. Keep established terminology consistent.
   8. Keep necessary domain terms. Define a term when the intended reader cannot infer its meaning.

3. **Structure.** Apply these rules:

   1. Each paragraph covers one topic and contains at most six sentences.
   2. Use numbered points for distinct ideas, steps, requirements or decisions.
   3. Use bullet points for supporting details.
   4. Use a list for three or more steps, conditions, requirements or comparable items.
      Use a numbered list when order matters.
   5. Break long explanations into structured points when this improves scanning.
   6. Use the minimum wording that preserves the full meaning and readability.

## 7. Strict Mode rules

Strict Mode includes every other Global Writing Rule and these four rules:

1. **Plain verbs.** Use a plain single verb in place of a phrasal verb when the meaning stays the same.

2. **Sentence length.** Limit each instruction or procedure sentence to 20 words.
   Limit each description sentence to 25 words.
   Exceed a limit only when precision requires it.

3. **Semicolons.** Use separate sentences in place of semicolons.

4. **Controlled terms.** Use each repeated controlled term in one consistent part of speech throughout the output.

## 8. Final compliance check

1. **Final review.** After writing, rewriting or translation, review the final output in its final language.
   Check it against these rules and the applicable Writing Mode.
   When Global Communication Rules apply, check it against them as well.

2. **Evidence.** An earlier source, draft or pre-translation version is not evidence of compliance.
   The final delivered content must satisfy every applicable rule.

3. **Correction.** Correct every non-compliant item before finalizing:

   - Wording.
   - Structure.
   - Terminology.
   - Ambiguity.
   - Sentence construction.
   - Paragraph structure.
   - Negative echo and defensive thinking.
   - Strict Mode rules.
